This guide installs Servflow on a machine you manage and gets you signed in to its dashboard. Self-host when you want your data on your own machine, or when your agents need to reach services on a private network. If you just want to use Servflow, sign up at [dash.servflow.io](https://dash.servflow.io) instead and follow [Your first agent](/quickstart).

## Before you begin

- 100 MB of free RAM. Servflow is a single Go binary with an embedded dashboard.
- A supported platform: Linux or macOS on x86_64 or arm64, or any host that runs Docker.
- Outbound network access to the LLM providers your agents use.

## Get a working configuration

Servflow reads a TOML configuration file, and you do not need to write one. Without a `--config` flag, `servflowai start` reads `~/.servflow/config.toml`. When that file does not exist, the server starts on the built-in defaults and writes no file. Relative paths resolve against `~/.servflow`, so the database is `~/.servflow/secrets.db` and the server listens on port `8080`. The first-run setup screen writes the file when you save it.

To see the configuration an instance is using, run:

```bash
servflowai resource settings view
```

For what each key means, see the [Configuration reference](/references/configuration).

## Install with Docker

1. Start the container with the port published and a volume mounted at `/data`:

   ```bash
   docker run -d \
     --name servflowai \
     -p 8080:8080 \
     -v servflowai-data:/data \
     servflow/servflowai:latest
   ```

   The image runs `servflowai start --dashboard`. Its environment points the database, memory folders, and shell folders into `/data`: `/data/secrets.db`, `/data/workspaces`, and `/data/work`. Keep the volume across upgrades.

   The image holds no configuration file. The first-run setup screen writes one to `~/.servflow/config.toml` inside the container, which survives `docker restart` but not a new container. To keep settings across upgrades, set them as environment variables with `-e`, as listed in the [Configuration reference](/references/configuration).

2. Open `http://localhost:8080/dashboard/`. The first-run setup screen appears.

## Install with Homebrew

The Homebrew formula installs the same binary on macOS and Linux.

1. Install the formula from the Servflow tap:

   ```bash
   brew install servflow/servflow/servflowai
   ```

2. Start the server with the dashboard enabled:

   ```bash
   servflowai start --dashboard
   ```

   The log prints `servflowai started`.

3. Open `http://localhost:8080/dashboard/`. The first-run setup screen appears.

## Install the binary

1. Download the archive for your platform from the [Releases](https://github.com/Servflow/servflowai/releases) page. Archives are named by platform, for example `servflowai_Linux_x86_64.tar.gz` or `servflowai_Darwin_arm64.tar.gz`.

2. Extract it and move the binary onto your `PATH`:

   ```bash
   tar -xzf servflowai_Linux_x86_64.tar.gz
   sudo mv servflowai /usr/local/bin/
   ```

3. Start the server with the dashboard enabled:

   ```bash
   servflowai start --dashboard
   ```

   The log prints `servflowai started`.

4. Open `http://localhost:8080/dashboard/`. The first-run setup screen appears.

## Install with npm

The npm package downloads the same binary for your platform. It supports macOS and Linux on x86_64 and arm64.

1. Install the package globally:

   ```bash
   npm install -g servflowai
   ```

2. Start the server with the dashboard enabled:

   ```bash
   servflowai start --dashboard
   ```

   The log prints `servflowai started`.

3. Open `http://localhost:8080/dashboard/`. The first-run setup screen appears.

## Create the first account

The dashboard requires an account. On a fresh instance the setup and registration screens are open until the first account exists, then they close.

<Steps>

<Step title="Set up your instance">
Under **Workspace directory**, choose the folder memory files are kept in, and choose whether to enable tracing. Optional: under **ServFlow authentication token**, paste your team's API key to connect the instance to servflow.io for trace export and Assist. Your answers are written to the configuration file.
</Step>

<Step title="Create your account">
Enter an email address and a password of at least 8 characters. This creates the first account. Creating further accounts requires being signed in.
</Step>

<Step title="Restart the server">
Stop the running process and start it again. The settings from step 1 are read when the server starts. With Docker, run `docker restart servflowai`.
</Step>

<Step title="Sign in">
Open the dashboard again and sign in with your credentials. The dashboard opens on the agents page. [Support agents](/concepts/support-agents) are not part of a self-hosted dashboard; they are in the hosted dashboard at [dash.servflow.io](https://dash.servflow.io) only.
</Step>

</Steps>

To run without the account gate on a trusted local machine, set `mode = "none"` under `[authentication]` in the configuration file.

## Verify

From the terminal, list the agents in the store. On a fresh instance the list is empty and the command exits without error:

```bash
servflowai resource agent list
```

If you use Docker, run it inside the container. The container's environment points the command at the same database as the server:

```bash
docker exec servflowai servflowai resource agent list
```

## Run it properly

For an instance that outlives a first try:

- **Encrypt secrets at rest.** Set `master_key` under `[sqlite]`, and set it through the `SERVFLOW_SQLITE_MASTER_KEY` environment variable rather than the file. See [Secrets](/concepts/secrets).
- **Back up the database.** The file set by `path` under `[sqlite]` holds your agents, integrations, providers, secrets, and accounts. Memory files are in the folder set by `root` under `[workspaces]`.
- **Do not expose the server directly.** Put it behind a reverse proxy with TLS.
- **Run it as a service.** Use a Docker restart policy, or a systemd unit for the binary, so it comes back after a reboot.
- **Pin a version.** Use a tagged image or package version rather than `latest`.
