A provider is a stored account with a model company, and the model to use, that sub-agents call models through. This page lists every provider type and its fields. Values are taken from the running binary. `servflowai resource provider describe --all` prints the same catalog, with each type's suggested models.

## How a provider is stored

- **Identity.** A provider has a numeric `id` and a `name`. A sub-agent refers to it by id, as `providerID`.
- **Type.** The type is fixed when the provider is created. `update` refuses a change of type.
- **Model.** The model is a field of the provider. A sub-agent has no model setting of its own.
- **API key.** `api_key` holds the key itself. It is not a reference to a stored [secret](/references/secrets). `list` and `get` do not return a provider's config.
- **Encryption.** When `master_key` is set under `[sqlite]`, provider config is encrypted at rest. See the [Configuration reference](/references/configuration).
- **When a change applies.** A provider is looked up each time an agent runs, so an update applies from the next run.
- **Deleting.** `delete` does not check whether agents use the provider. An agent that names a deleted provider fails at its next run, and cannot be saved again until it names a provider that exists.

## Provider types

### claude

Anthropic Claude models.

| Key | Label | Type | Required | Description |
|---|---|---|---|---|
| `api_key` | API Key | password | Yes | The Anthropic API key. |
| `model` | Model | string | No | The model to call. Defaults to the type's suggested model. |

### openai

OpenAI models.

| Key | Label | Type | Required | Description |
|---|---|---|---|---|
| `api_key` | API Key | password | Yes | The OpenAI API key. |
| `model` | Model | string | No | The model to call. Defaults to the type's suggested model. |

### openrouter

OpenRouter, one key for many companies' models through an OpenAI-compatible endpoint.

| Key | Label | Type | Required | Default | Description |
|---|---|---|---|---|---|
| `api_key` | API Key | password | Yes | none | The OpenRouter API key. |
| `defaultEndpoint` | Endpoint | string | No | `https://openrouter.ai/api/v1/chat/completions` | The chat completions URL. |
| `model` | Model | string | No | The type's suggested model | The model to call, as `company/model`. |
| `reasoning` | Reasoning | select | No | `default` | One of `default`, `none`, `minimal`, `low`, `medium`, `high`. `default` sends no reasoning setting and lets the model decide. Any other value is sent as the reasoning effort. |

### litellm

A LiteLLM proxy, a self-hosted OpenAI-compatible gateway.

| Key | Label | Type | Required | Description |
|---|---|---|---|---|
| `api_key` | API Key | password | Yes | The LiteLLM API key. |
| `defaultEndpoint` | Base URL | string | Yes | The proxy's chat completions URL, such as `http://localhost:4000/v1/chat/completions`. |
| `model` | Model | string | No | The model to call. Defaults to the type's suggested model. |

### qwen

Alibaba Qwen models.

| Key | Label | Type | Required | Default | Description |
|---|---|---|---|---|---|
| `api_key` | API Key | password | Yes | none | The Qwen API key. |
| `defaultEndpoint` | Endpoint | string | No | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1/chat/completions` | The chat completions URL. |
| `model` | Model | string | No | The type's suggested model | The model to call. |

## Managing providers outside the dashboard

### CLI

| Command | What it does |
|---|---|
| `servflowai resource provider list` | Lists providers, without config. |
| `servflowai resource provider get <id>` | Gets one provider, without config. |
| `servflowai resource provider create -f <file>` | Creates a provider. |
| `servflowai resource provider update <id> -f <file>` | Renames a provider and overlays the config fields given onto the stored ones. |
| `servflowai resource provider delete <id>` | Deletes a provider. |
| `servflowai resource provider types` | Lists the provider types. |
| `servflowai resource provider describe [type...]` | Describes types, their fields, and their suggested models. Pass `--all` for every type. |

The body names the provider, its type, and its config:

```json
{
  "name": "OpenAI production",
  "type": "openai",
  "config": { "api_key": "sk-...", "model": "gpt-4.1" }
}
```

`create` validates the config by building the client it describes. `--dry-run` validates and prints the result without writing.

### MCP

The management server at `/api/mcp` exposes `list_providers`, `get_provider`, `create_provider`, `update_provider`, `delete_provider`, `list_provider_types`, and `describe_provider_type`.
