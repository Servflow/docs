A secret is a named, stored value that configs refer to by name. This page describes how secrets are stored, looked up, and managed. For what secrets are for, see [Secrets](/concepts/secrets).

## How a secret is stored

- **Identity.** A secret has a numeric `id`, a `name`, and an optional `description`. Configs refer to it by name. A name cannot be changed after creation.
- **Value.** The value is never returned. `list` and `get` return names and metadata only. `update` changes the value only.
- **Storage.** Secrets are rows in the SQLite store, at the path set by `path` under `[sqlite]`.
- **Encryption.** When `master_key` is set under `[sqlite]`, secret values are encrypted at rest. `master_key` is empty unless you set it, and an empty key stores values as plain text. It can also be set with `SERVFLOW_SQLITE_MASTER_KEY`. See the [Configuration reference](/references/configuration).

## Where a secret can be referenced

| Place | How |
|---|---|
| A prompt, a tool's action fields, a context step's fields, a guard | The `secret` template function: `{{ secret "name" }}` |
| An entry handler's settings | The `secret` template function. It is the only template function these settings accept. |
| An integration's field | The field's value is `{"secret": "<name>"}` instead of `{"value": ...}`. See [Integrations](/references/integrations). |
| An MCP tool's token | The token names a stored secret. See [Tools](/references/tools). |

A provider's `api_key` is not a secret reference. It holds the key itself. See [Providers](/references/providers).

## Lookup order

`secret "name"` returns the first non-empty value found, in this order:

1. An environment variable whose name is exactly the secret's name, with no prefix and no change of case.
2. The SQLite store.

An environment variable therefore overrides a stored secret of the same name. A name that matches nothing returns an empty string, not an error.

## When a changed value applies

| Where the secret is referenced | When the new value is used |
|---|---|
| A prompt, a tool's action fields, a context step's fields, a guard | The next run. The value is looked up on each run. |
| An entry handler's settings, an integration's field | The next config reload. The value is looked up when configs load. |

Saving any agent in the dashboard reloads configs. So does any `resource` CLI command that writes, unless it is run with `--reload=false`. Changing a secret's value in the dashboard does not reload configs.

## Managing secrets outside the dashboard

### CLI

| Command | What it does |
|---|---|
| `servflowai resource secret list` | Lists secrets: names and metadata only. |
| `servflowai resource secret get <id>` | Gets one secret, without its value. |
| `servflowai resource secret create --name <name> --value <value>` | Creates a secret. `--description` is optional. |
| `servflowai resource secret update <id> --value <value>` | Replaces a secret's value. |
| `servflowai resource secret delete <id>` | Deletes a secret. |

`create`, `update`, and `delete` take `--dry-run`, which validates without writing, and `--reload`, which is on by default and signals a running server to reload.

### MCP

The management server at `/api/mcp` exposes `list_secrets`, `create_secret`, `update_secret`, and `delete_secret`.
