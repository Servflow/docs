This page lists every integration type built into Servflow, and the types Servflow Cloud adds. The apps Servflow Cloud connects to, such as Gmail or Jira, are listed in the [integrations directory](https://servflow.io/integrations). Each type's section says what uses it and lists its fields and its body in a file. `servflowai resource integration describe --all` prints the same catalog. For what an integration is, see [Integrations](/concepts/integrations). To add one in the dashboard, see [Add an integration](/guides/add-an-integration).

In a body, `name` is what you call the integration; Servflow generates its `integrationId` from it. Each field of `config` holds either a literal, as `{"value": ...}`, or the name of a stored secret, as `{"secret": "<secret name>"}`. Use a secret for every password field. A secret that a body names has to exist before the integration is created. The commands that take a body are in the [CLI reference](/references/cli#integration).

An integration connected through OAuth, such as Notion, cannot be used until its sign-in finishes.

| Type | Name in the dashboard | Guided setup | Used by |
|---|---|---|---|
| [`binance`](#binance) | Binance | No | `binance/*` actions |
| [`chromium`](#chromium) | Chromium | No | `chromium/*` actions |
| [`discord`](#discord) | Discord | Yes | `discord/*` actions, `discord_gateway` entry |
| [`gitea`](#gitea) | Gitea | No | `gitea/*` actions, replies from a `gitea_webhook` entry |
| [`github_app`](#github_app) | GitHub App | Yes | `github_fetch` and `github_post` actions, `github_webhook` entry |
| [`mongo`](#mongo) | MongoDB | No | `fetch`, `delete`, `authenticate`, and `mongoquery` actions |
| [`notion_mcp`](#notion_mcp) | Notion | Yes | MCP server tools |
| [`qdrant`](#qdrant) | Qdrant | No | `storevector` and `fetchvectors` actions |
| [`sql`](#sql) | SQL Database | No | `fetch`, `delete`, and `authenticate` actions |
| [`telegram_bot`](#telegram_bot) | Telegram Bot Chat | No | `telegram_webhook` entry |
| [`slack:bot`](#servflow-slackbot), Servflow Cloud only | Servflow SlackBot | Yes | `slack_bot` entry, `slack:send_message` action |
| [`composio:<id>`](#composio-integrations), Servflow Cloud only | The app's name | Depends on the app | The app's `external:` actions, `app_event` entry |

A type with a guided setup opens its own set of screens in the dashboard. Every other type opens a form with one input for each field. OAuth-guided integrations can appear as **Not connected** until the provider approval finishes; use the row's **Connect integration** action to retry the approval.

## Types

### binance

Binance cryptocurrency exchange integration for trading operations.

| Key | Label | Type | Required | Default |
|---|---|---|---|---|
| `api_key` | API Key | password | Yes | none |
| `secret_key` | Secret Key | password | Yes | none |
| `testnet` | Testnet | boolean | No | `false` |
| `timeout` | Timeout (seconds) | number | No | `30` |

```json
{
  "name": "My Binance",
  "type": "binance",
  "config": {
    "api_key": { "secret": "binance-api-key" },
    "secret_key": { "secret": "binance-secret-key" },
    "testnet": { "value": true }
  }
}
```

### chromium

Chromium browser automation integration for web scraping and testing.

| Key | Label | Type | Required | Default |
|---|---|---|---|---|
| `headless` | Headless Mode | boolean | No | `true` |
| `timeout` | Timeout (seconds) | number | No | `30` |

```json
{
  "name": "Browser",
  "type": "chromium",
  "config": {
    "headless": { "value": true },
    "timeout": { "value": 30 }
  }
}
```

### discord

A Discord bot for one server. It reads that server, and sends messages anywhere it can. To run an agent as a Discord bot, see [Connect an agent to Discord](/guides/connect-an-agent-to-discord).

| Key | Label | Type | Required | Default |
|---|---|---|---|---|
| `bot_token` | Bot Token | password | Yes | none |
| `guild_id` | Server | string | Yes | none |

```json
{
  "name": "My Discord bot",
  "type": "discord",
  "config": {
    "bot_token": { "secret": "discord-bot-token" },
    "guild_id": { "value": "905712398471923849" }
  }
}
```

### gitea

A Gitea server and the account the agent acts as on it. Receiving a Gitea webhook needs no integration, because that secret belongs to the webhook and is set on the entry.

| Key | Label | Type | Required | Default |
|---|---|---|---|---|
| `base_url` | Server URL | string | Yes | none |
| `token` | Access Token | password | Yes | none |

```json
{
  "name": "My Gitea",
  "type": "gitea",
  "config": {
    "base_url": { "value": "https://gitea.example.com" },
    "token": { "secret": "gitea-access-token" }
  }
}
```

### github_app

A GitHub App's credentials. The GitHub actions mint installation tokens with them, and the App's deliveries are signed with its webhook secret.

In the dashboard, the guided setup creates the App and fills in these fields for you.

| Key | Label | Type | Required | Default |
|---|---|---|---|---|
| `base_url` | Base URL | string | No | `https://api.github.com` |
| `client_id` | Client ID | string | Yes | none |
| `installation_id` | Installation ID | string | Yes | none |
| `pem` | Private Key (PEM) | password | Yes | none |
| `webhook_secret` | Webhook Secret | password | Yes | none |

```json
{
  "name": "My GitHub App",
  "type": "github_app",
  "config": {
    "client_id": { "value": "Iv1.0000000000000000" },
    "installation_id": { "value": "12345678" },
    "pem": { "secret": "github-app-private-key" },
    "webhook_secret": { "secret": "github-app-webhook-secret" }
  }
}
```

### mongo

MongoDB database integration for document storage and retrieval.

| Key | Label | Type | Required | Default |
|---|---|---|---|---|
| `connectionString` | Connection String | password | Yes | none |
| `dbName` | Database Name | string | Yes | none |

```json
{
  "name": "App database",
  "type": "mongo",
  "config": {
    "connectionString": { "secret": "mongo-uri" },
    "dbName": { "value": "app" }
  }
}
```

### notion_mcp

A Notion workspace connected through Notion's MCP server. It has no fields in the form. In the dashboard, give it a name and sign in to Notion. An MCP server tool can then use it as its access token.

Each `notion_mcp` integration is one Notion workspace connection. To connect another workspace, create another Notion integration with a different name and complete its sign-in.

### qdrant

Qdrant vector database for similarity search and vector storage.

| Key | Label | Type | Required | Default |
|---|---|---|---|---|
| `url` | URL | string | Yes | none |

```json
{
  "name": "Vectors",
  "type": "qdrant",
  "config": {
    "url": { "value": "http://localhost:6333" }
  }
}
```

### sql

SQL database integration supporting PostgreSQL and MySQL.

| Key | Label | Type | Required | Default | Values |
|---|---|---|---|---|---|
| `connectionString` | Connection String | password | Yes | none | none |
| `type` | Database Type | select | Yes | none | `postgres`, `mysql` |

```json
{
  "name": "Orders database",
  "type": "sql",
  "config": {
    "connectionString": { "secret": "orders-db-url" },
    "type": { "value": "postgres" }
  }
}
```

### telegram_bot

A Telegram bot: the token BotFather issued, and optionally the secret its webhook is registered with. Point the bot's webhook at one agent only.

| Key | Label | Type | Required | Default |
|---|---|---|---|---|
| `secret_token` | Webhook Secret Token | password | No | none |
| `token` | Bot Token | password | Yes | none |

```json
{
  "name": "My Telegram bot",
  "type": "telegram_bot",
  "config": {
    "token": { "secret": "telegram-bot-token" },
    "secret_token": { "secret": "telegram-webhook-secret" }
  }
}
```

## Servflow Cloud types

These types are added by the hosted service. A self-hosted catalog does not list them.

### Servflow SlackBot

Type `slack:bot`. Servflow Cloud only. A Slack workspace with the Servflow bot installed. Agents answer as the bot through a [`slack_bot`](/references/entry-handlers#slack_bot) trigger, and send direct messages as it with the [`slack:send_message`](/references/actions#servflow-cloud-actions) action.

It has no fields. In the dashboard, click **Add to Slack** on the **Integrations** page and approve the install in Slack; the install fills in the workspace and the bot's token. An integration created any other way cannot be enabled until the workspace is installed.

### Composio integrations

Type `composio:<id>`, one type for each app Servflow Cloud connects to. Servflow Cloud only. An integration of one of these types is a connected account of that app, such as a Gmail inbox. The app's actions, of type `external:<ACTION>`, and the `app_event` trigger take it in their `integration` field.

`list_integration_types` and `describe_integration_type` on the [Servflow MCP server](/references/mcp-server) list the types and their fields. Each field is one the app asks for, such as an API key. An app that signs in through OAuth runs its sign-in in the dashboard when you add the integration.
