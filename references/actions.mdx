     6	
     7	An action is one thing an agent can do: send a Discord message, fetch a web address, read a pull request. An agent runs an action in two places. A [tool](/concepts/tools) runs one when the agent decides to use it. A [context step](/concepts/context-fetching) runs one every time, before the agent starts. This page lists every action with its fields. `servflowai resource action describe --all` prints the same catalog.

    64	## How an action is written in a config file
    65	
    66	As a context step, an action is an `id`, a `type`, and a `config` that maps each field to a string. Every string is a template.
    67	
    68	```yaml
    69	- id: repo
    70	  type: http
    71	  config:
    72	    method: GET
    73	    url: 'https://api.github.com/repos/{{ body "repo" }}'
    74	```
    75	
    76	As a tool, the same action goes under `actionConfig`, and each field's value is wrapped in an object. `type: raw` means you set the value. `type: param` means the agent fills it in when it uses the tool, and `value` names the input it is asked for.
    77	
    78	```yaml
    79	actionConfig:
    80	  type: http
    81	  config:
    82	    method:
    83	      type: raw
    84	      value: GET
    85	    url:
    86	      type: param
    87	      value: address
    88	```
    89	
    90	Two differences follow from this:
    91	
    92	- **Field types.** A step's values are all strings, so a field of type `map` cannot be written as a map in a step. A tool's `raw` value can be a string, a number, a boolean, a list, or a map.
    93	- **Who fills a field.** Only a tool has `param`.
    94	
    95	The examples below show each action as a step. An action with a required `map` field is shown as a tool. The rest of a step and of a tool is in the [CLI reference](/references/cli#contextgroups).
    96	
    97	In the field tables, **Type** is the binary's field type: `string`, `text_area` (a long string), `boolean`, `map`, `file`, or `integration` (the id of a stored integration).

    99	## Discord
   100	
   101	### discord/sendmessage
   102	
   103	Sends a message to a Discord channel, a thread, or a person.
   104	
   105	| Key | Label | Type | Required | Default | Values |
   106	|---|---|---|---|---|---|
   107	| `integration` | Discord Bot | integration | Yes | none | A `discord` integration |
   108	| `content` | Message Content | string | Yes | none | The message to send |
   109	| `channel_id` | Channel ID | string | No | none | The channel to post in |
   110	| `user_id` | User ID | string | No | none | Sends a direct message to this person instead of posting in a channel |
   111	| `thread_id` | Thread ID | string | No | none | Sends to an existing thread |
   112	| `create_thread` | Create Thread | boolean | No | `false` | Creates a new thread for this message |
   113	| `thread_name` | Thread Name | string | No | none | The new thread's name. Needed when `create_thread` is `true` |
   114	| `reply_to` | Reply To | string | No | none | The id of the message this one replies to |
   115	| `mentions` | Mentions | string | No | `none` | Who the message may notify: `none`, `reply`, `users`, `roles`, `everyone` |
   116	| `split` | Split Long Messages | boolean | No | `true` | Posts text over 2000 characters as several messages |
   117	
   118	```yaml
   119	- id: announce
   120	  type: discord/sendmessage
   121	  config:
   122	    integration: my-discord-bot
   123	    channel_id: "112233445566778899"
   124	    content: 'New question from {{ .discord.display_name }}: {{ .discord.content }}'
   125	```
   126	
   127	As a tool that always posts in one channel and lets the agent write the text:
   128	
   129	```yaml
   130	actionConfig:
   131	  type: discord/sendmessage
   132	  config:
   133	    integration:
   134	      type: raw
   135	      value: my-discord-bot
   136	    channel_id:
   137	      type: raw
   138	      value: "112233445566778899"
   139	    content:
   140	      type: param
   141	      value: message
   142	```

   300	## Web requests and code
   301	
   302	### http
   303	
   304	Calls a web address and returns the response.
   305	
   306	| Key | Label | Type | Required | Default | Values |
   307	|---|---|---|---|---|---|
   308	| `url` | URL | string | Yes | none | The address to call |
   309	| `method` | HTTP Method | string | Yes | `GET` | `GET`, `POST`, `PUT`, `DELETE`, `PATCH` |
   310	| `headers` | Headers | map | No | none | Header names and values |
   311	| `body` | Request Body | map | No | none | The request body. See below |
   312	| `responsePath` | Response Path | string | No | none | A path into the JSON response. Only that part is returned |
   313	| `expectedResponseCode` | Expected Response Code | string | No | empty | The status code that counts as success, such as `200` |
   314	| `failIfResponseEmpty` | Fail if Response Empty | boolean | No | `true` | Treats an empty response as a failure |
   315	
   316	```yaml
   317	- id: repo
   318	  type: http
   319	  config:
   320	    method: GET
   321	    url: 'https://api.github.com/repos/{{ body "repo" }}'
   322	    responsePath: description
   323	```
   324	
   325	As a tool, with headers and a body. Write `body` as a map. Each value is filled in on its own and then encoded as JSON, so quotes and line breaks in a value need no escaping.
   326	
   327	```yaml
   328	actionConfig:
   329	  type: http
   330	  config:
   331	    method:
   332	      type: raw
   333	      value: POST
   334	    url:
   335	      type: raw
   336	      value: https://api.example.com/tickets
   337	    headers:
   338	      type: raw
   339	      value:
   340	        Authorization: 'Bearer {{ secret "tickets-api-key" }}'
   341	    body:
   342	      type: raw
   343	      value:
   344	        title: '{{ tool_param "title" }}'
   345	        details: '{{ tool_param "details" }}'
   346	```
   347	
   348	### javascript
   349	
   350	Runs JavaScript. The script defines a function named `servflowRun`, and what the function returns is the action's result. The function receives three arguments: the run's variables, the body of the request that started the run, and the request's parameters. The script cannot call web addresses, and has no `require`.
   351	
   352	| Key | Label | Type | Required | Default | Values |
   353	|---|---|---|---|---|---|
   354	| `script` | Script | text_area | Yes | none | JavaScript that defines `servflowRun` |
   355	| `dependencies` | Dependencies | text_area | No | none | JavaScript loaded before the script, such as a bundled library |
   356	
   357	```yaml
   358	- id: customer
   359	  type: javascript
   360	  config:
   361	    script: |
   362	      function servflowRun(variables, requestBody, params) {
   363	        var request = JSON.parse(requestBody);
   364	        return { name: request.name.trim(), vip: request.orders > 10 };
   365	      }
   366	```
   367	
   368	A later step or a prompt reads the result as `{{ .customer.name }}`.
   369	
   370	### shell
   371	
   372	Runs a shell script, with the shell's full syntax. The script starts in a sandboxed folder of its own that is deleted when the run ends, and it cannot read the server's own files. The instance's `[shell]` settings decide how it is sandboxed.
   373	
   374	| Key | Label | Type | Required | Default | Values |
   375	|---|---|---|---|---|---|
   376	| `script` | Script | string | Yes | none | The script to run |
| `env` | Environment | array | No | none | Each entry: a name and one source (integration, secret, or literal)
   377	
   378	```yaml
   379	- id: today
   380	  type: shell
   381	  config:
   382	    script: date +%A
    env:
      - name: GH_TOKEN
        integrationId: github-app
      - name: NPM_TOKEN
        secretId: npm-publish
      - name: REPO
        value: servflow/servflowai
   383	```

   469	## Databases
   470	
   471	`fetch` and `delete` take `filters`: a list of conditions, each with a `field`, an `operation`, and a `comparator`. The operations are `==`, `!=`, `>`, `<`, `>=`, `<=`, and `like`.
   472	
   473	### fetch
   474	
   475	Reads rows from a table of a SQL or MongoDB database.
   476	
   477	| Key | Label | Type | Required | Default | Values |
   478	|---|---|---|---|---|---|
   479	| `integration` | Database Integration | integration | Yes | none | A `sql` or `mongo` integration |
   480	| `table` | Table | string | Yes | none | The table or collection |
   481	| `filters` | Filters | map | No | none | Conditions a row has to meet |
   482	| `single` | Single Result | boolean | No | `false` | Returns one row instead of a list |
   483	| `failIfEmpty` | Fail if Empty | boolean | No | `true` | Treats no rows as a failure |
   484	| `shouldFail` | Should Fail | boolean | No | `false` | Whether an error fails the action |
   485	| `datasourceOptions` | Datasource Options | map | No | none | Extra options for the database |
   486	
   487	```yaml
   488	- id: plans
   489	  type: fetch
   490	  config:
   491	    integration: orders-db
   492	    table: plans
   493	    failIfEmpty: "false"
   494	```
   495	
   496	As a tool, with a filter the agent fills in:
   497
