Connect an AI coding agent, such as Claude Code or Codex, to the Servflow MCP server, and then ask it to build and enable your team's agents and support agents for you. Every tool it can call is listed on [The Servflow MCP server](/references/mcp-server).

## Before you begin

- A Servflow Cloud team. Sign up at [dash.servflow.io](https://dash.servflow.io). A self-hosted instance has no MCP server; manage it with the [`servflowai resource` CLI](/references/cli).
- An MCP client that supports the streamable HTTP transport, such as Claude Code.
- Your team's API key. In the dashboard, open **Settings** > **MCP connection** and copy **Your API key**.

The API key gives full control of your team's agents, integrations, and secrets. Keep it out of files you commit.

## Connect your MCP client

### Claude Code

Add the server, with your key in place of `<key>`:

```bash
claude mcp add --transport http servflow https://server.servflow.io/api/mcp \
  --header "Authorization: Bearer <key>"
```

To confirm Claude Code reaches the server, run `claude mcp list`. It checks each server and shows `servflow` as connected.

### Another client

Add a server that uses the streamable HTTP transport, with:

- **URL**: `https://server.servflow.io/api/mcp`.
- **Header**: `Authorization` set to `Bearer <key>`.

## Check the connection

Ask the AI agent:

```text
List my Servflow agents.
```

It calls `list_configs` and answers with each agent's name, `config_id`, and whether it is enabled. An empty list on a new team is a working connection. If the call fails with `unauthorized` or `invalid auth token`, copy the key again from **Settings** > **MCP connection** and add the server again.

## Create an agent

Describe the agent you want, and ask the AI agent to build it with the Servflow tools. For example:

```text
Create a Servflow agent called "Shop questions" that answers POST requests on
/shop-questions. It reads the question from the "question" field of the JSON
body and answers in two sentences. Validate it, create it, and enable it.
```

The AI agent works through these steps. You can ask for each one by name.

<Steps>

<Step title="Start from the example and the schema">
`config_example` returns a small valid agent, and `config_schema` returns the shape every agent must have. The fields are described in [The shape of an agent](/references/cli#the-shape-of-an-agent).
</Step>

<Step title="Find the pieces">
`list_entry_handlers` and `describe_entry_handler` describe the triggers, `list_actions` and `describe_action` the actions, and `list_template_functions` what a prompt can read. `list_providers` and `list_integrations` give the ids the agent can name. A sub agent can use the built-in provider, `native`, with no provider of your own.
</Step>

<Step title="Validate">
`validate_config` checks the agent without saving it, and says what is wrong. The AI agent fixes the body and validates again until it answers `"valid": true`.
</Step>

<Step title="Create">
`create_config` saves the agent and returns its `config_id`. The agent is saved disabled, so it does not run yet.
</Step>

<Step title="Enable">
`set_config_enabled` with `enabled: true` builds the agent and runs it. If it cannot run, for example because a provider or integration it names does not exist, the tool says why and the agent stays disabled.
</Step>

</Steps>

To change an agent later, ask for the change. The AI agent calls `update_config` with the whole agent, then `set_config_enabled` again: an enabled agent keeps running its previous version until it is enabled again.

### Verify

Ask the AI agent to list your agents again. The new agent shows `enabled: true`, and it appears on the **Agents** page of the dashboard. Send a request to the agent's path on your team's agents address to see it answer.

## Create a support agent

A support agent answers your customers on a channel such as the live chat. To create one, describe it and ask the AI agent to build it. For example:

```text
Create a Servflow support agent called "Shop help" that answers on our live
chat with the native provider and answers questions about orders and returns.
Enable it, then point our live chat at it for shop.example.com.
```

The AI agent works through these steps.

<Steps>

<Step title="Create">
`create_support_agent` saves the support agent and returns its `id`. It is saved disabled, so it does not answer customers yet. With no guardrails in the request, it gets `answers_from_business`.
</Step>

<Step title="Enable">
`set_support_agent_enabled` with `enabled: true` checks your plan and builds the support agent. If it cannot start, the tool says why and the support agent stays disabled.
</Step>

<Step title="Connect the live chat">
`set_livechat` saves the live chat with `agent_id` set to the support agent and `websites` set to your site. `get_livechat` returns what is saved.
</Step>

</Steps>

To change a support agent later, ask for the change. The AI agent calls `update_support_agent`, then `set_support_agent_enabled` again: an enabled support agent keeps answering with its previous version until it is enabled again.

Ask the AI agent to change support agents only with these tools. `list_configs` lists support agents too, as kind `support`, but the agent tools do not keep a support agent's channels, guardrails, and handoffs in step.

### Verify

Ask the AI agent to list your support agents. The new support agent shows `enabled: true`, and it appears on the **Support agents** page of the dashboard.
