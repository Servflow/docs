# Plans

The standard place for documentation planning documents: audits, rewrite
proposals, and migration plans. They record what was found and what was
decided, not how the product works.

Everything in this folder except this README is ignored by git. The plans are
working notes for whoever is writing the docs, and this is a public repository,
so they stay on the machine that wrote them. Anything a reader needs belongs in
a page listed in `docs.json` instead.

Name a new plan in lower kebab case after the change it describes, such as
`action-reference-update-plan.md`. When a plan has been carried out, say so at
the top rather than deleting it, so the reasoning behind a change stays
findable locally.
